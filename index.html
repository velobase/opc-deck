为了解决这个问题，我们做了 Velobase Harness，一个开源的全栈 AI SaaS 框架。它的核心设计很简单：把我们踩过的坑全部内置为可插拔模块，你填一个环境变量就自动启用，不需要改代码。接下来我不讲框架架构，直接讲 5 个具体问题，讲清楚它们是什么、为什么你可能不知道、我们怎么处理的。

Action 1 · 支付掉单

Stripe Webhook 会丢。
用户付了钱，你不知道。

问题

网络抖动、服务重启、部署间隙——Webhook 没收到。
订单卡在 PENDING，用户付了钱没权益。

处理

每分钟扫描 PENDING 订单，主动向 Stripe 查询真实状态。
每小时全量对账，确保没有一笔遗漏。

第一个知识点：支付掉单。你接了 Stripe，用户付款成功后，Stripe 会通过 Webhook 通知你。但 Webhook 本质上是一个 HTTP 请求，网络会抖动、你的服务可能刚好在重启、部署间隙可能有几秒收不到请求。这时候用户实际已经付了钱，但你的系统不知道。用户会来找你。你如果没有自动补偿机制，就得手动处理。Harness 的做法是：后台每分钟扫描一次所有超过 5 分钟仍然是 PENDING 的订单，主动去 Stripe API 查一下真实状态。如果已经 succeeded，就自动完成权益发放。每小时还有一次全量对账。这样不论 Webhook 丢不丢，你都不会漏单。

Action 2 · Gmail 别名滥用

同一个人，无限个邮箱。

john.doe@gmail.com

johndoe@gmail.com

j.o.h.n.d.o.e@gmail.com

johndoe+free1@gmail.com

↑ 全是同一个人。Gmail 忽略点和加号后缀。

处理

注册时自动规整化：去掉点、去掉 + 后缀、统一比对。
同一个真实邮箱只能注册一次。

第二个：Gmail 别名滥用。Gmail 有两个特性大部分开发者不知道：第一，邮箱用户名里的点会被忽略，john.doe 和 johndoe 是同一个邮箱；第二，加号后面的内容也被忽略，johndoe+anything 和 johndoe 是同一个邮箱。这意味着一个人可以用 johndoe、j.ohndoe、johndoe+1、johndoe+2…… 注册无数个账号。如果你的产品有新用户赠送（比如赠 100 积分），一个人可以轻松刷走上万积分。Harness 在注册环节自动做邮箱规整化：去掉所有点、去掉加号后缀，用规整后的邮箱做唯一性校验。同一个真实邮箱只能注册一次。

Action 3 · 广告归因

前端追踪被 AdBlock 吃掉。
你的广告数据全是假的。

问题

30%+ 用户装了广告拦截。前端 gtag 转化事件根本发不出去。
你看到的 ROAS 数据严重失真。

处理

三层链路：
① 落地页自动采集 gclid / utm_source / fbclid → Cookie
② 注册时写入 User 表，绑定用户身份
③ 付费成功后，服务端离线回传 Google Ads API

第三个：广告归因。你花了钱投 Google Ads，想知道哪个关键词带来了付费用户。常规做法是前端装 gtag 追踪代码。但现实是，30% 以上的用户装了 AdBlock 或类似插件，这些插件会直接屏蔽 gtag 请求。也就是说你的转化数据有三分之一是丢失的。你算出来的 ROAS（广告回报率）是假的，你可能在亏钱的渠道上加预算。Harness 的做法是三层链路。第一层：用户从广告点进来的时候，URL 里有 gclid 这个参数，框架自动采集存到 Cookie。第二层：用户注册时，把 Cookie 里的 gclid 写入数据库 User 表，跟用户身份绑定。第三层：当这个用户某天付费了，后台通过 BullMQ 队列，每 5 分钟批量将转化事件通过 Google Ads API 从服务端上传。服务端回传不经过浏览器，AdBlock 拦不住。这样你的归因数据是准的。

Action 4 · 签到衰减

新用户赠送如果不衰减，
获客成本永远不收敛。

问题

每天赠 10 积分，用户永远不需要付费。
第 100 天注册的用户和第 1 天享受一样的待遇，成本线性增长。

处理

连续签到衰减：第 1 天赠 10，第 2 天赠 9，第 3 天赠 8……
最终收敛到一个最低值。促进留存的同时控制成本。

第四个：签到衰减。很多 AI 产品为了拉新会给新用户每日赠送积分。看起来很合理，但如果每天赠送的量是固定的，那用户永远用免费额度就够了，他没有动力付费。而且你的用户越来越多，每天发出去的积分也越来越多，这是一条线性增长的成本线，永远不收敛。Harness 的做法是签到衰减：第 1 天赠 10 积分，第 2 天赠 9，第 3 天赠 8，逐渐衰减到一个最低值（比如 2）。这样做的效果是：新用户前几天能充分体验产品（促激活），但几天后免费额度不够用了，自然产生付费动力。同时总赠送量是有上界的，成本可控。

Action 5 · 先发后收

反滥用不能让正常用户等。

问题

如果注册时同步做所有检测（IP 查询、设备指纹、邮箱校验），
正常用户也要等 2-3 秒。99% 的人被 1% 的坏人拖慢。

处理

注册时只做轻量检测（临时邮箱黑名单），立即放行。
异步检测同 IP 多账号、设备指纹关联。
确认滥用后，自动回收已发放的积分。

第五个：先发后收。反滥用是必须做的，但怎么做很讲究。最直觉的做法是在注册时同步做所有检查：查 IP、查设备指纹、查邮箱是否关联其他账号。但这些检查加起来要 2-3 秒。99% 的正常用户会因为 1% 的坏人，体验到一个很慢的注册流程。Harness 的策略是「先发后收」：注册时只做最轻量的检测——查一下是不是一次性邮箱，如果不是就立即放行，发放新用户积分。然后异步在后台做重量级检测：同 IP 多账号、设备指纹关联、行为模式分析。如果确认是滥用，再自动把已经发给他的积分回收。这样正常用户体验零延迟，坏人最终也拿不到好处。
