先把底牌亮出来。我自己一个人做了一个 AI SaaS 产品，用的就是今天要讲的这套框架，真金白银赚了几万美金。所以今天聊的东西不是理论，是从真实项目里抽出来的。

AI 写代码越来越强了，
但大部分一人公司，还是不赚钱。

最容易有的误诊：

「是不是 AI 写的业务还不够复杂？」

过去一年，我身边做独立开发的朋友越来越多。大家每天在群里惊叹 Cursor 多牛、Claude 多懂我。但一到月底看账单，没几个人真正赚到了钱。我统计了一下身边的人，发现大家的第一反应都是——是不是我让 AI 写的东西还不够复杂？但我看了很多死掉的项目，发现根本不是这么回事。

我们用 AI 做出了「功能」

但没做成「生意」

一个能收钱的 SaaS，需要支付网关、积分消耗、防刷隔离、分销裂变……

痛点不在 AI 的智商，在于缺少一张「商业化的图纸」。

很多工程师能让 AI 写出一个很炫的网页、一个好用的工具。但一个能向用户收钱的 SaaS，它需要支付、需要积分管理、需要防刷、需要分销。很多纯技术背景的开发者，原来没接触过完整的商业闭环，一开始很难把这些需求规划全面。你都不知道要让 AI 写什么，AI 再聪明也帮不了你。

AI 可以一句话搞定：

登录页 CRUD 大模型对话接口 Landing Page

但 AI 没法自己规划这些：

精细化多端登录 积分+订阅+多网关计费 PostHog A/B 测试 反滥用策略 分销系统

不是写不出来，是大部分人不知道要写这些。

具体点说。让 AI 写个登录页、写个 CRUD、接个大模型，这些一分钟就搞定了。但你想让 AI 帮你设计一套精细化的多端登录——Web、移动端、Telegram Bot、API Token 四条路径统一身份——它做不到。不是 AI 写不出那个代码，而是你不知道要提这个需求。积分怎么和订阅叠加？A/B 测试怎么从框架层集成？反滥用的风险评分怎么设？分销佣金怎么防刷？这些全是业务判断，不是代码问题。大部分人的精力就死在补齐这些东西的路上了。

开源 · velobase/velobase-harness

把商业化底座标准化

我把赚到钱的这套框架开源了。
它不只是代码——是通过结构和文档告诉你：一个商业化 SaaS 应该长什么样。

有了图纸，AI 才能精准施工。

所以我做了一件事。我把自己这个项目底下跑了大半年的框架抽出来，开源了，叫 Velobase Harness。它最大的价值不是那几万行代码本身，而是通过目录结构和文档，告诉你——你要做一个能赚钱的 SaaS，你需要准备哪些基础能力。说白了它是我踩了无数坑之后，沉淀出来的一套业务最佳实践。你有了这张图纸，再让 AI 去写代码，效率完全不一样。

开箱即用的商业化底座

计费引擎

充值、赠送、优惠码叠加
Stripe / Crypto / Telegram Stars

反滥用防火墙

一次性邮箱屏蔽、速率限制
风险评分、同 IP 多号判定

数据与增长

原生集成 PostHog
每次业务变更都能被测量

分销系统

推荐追溯、佣金模型
一人公司的裂变抓手

具体有什么呢？计费引擎——不是简单接个 Stripe 就完了，是积分充值、每日赠送、优惠码叠加、多网关切换这一整套。反滥用——一次性邮箱检测、频率限制、风险评分，这些不是写个 rate limiter 就行的，每个参数都是业务判断。PostHog A/B 测试从框架层集成好了，改了定价就能跑实验。分销系统佣金追踪、提现管理、防刷也都有。 举个例子，我刚上线的时候（TODO：补充一个真实的踩坑故事，比如被薅羊毛、被一次性邮箱刷爆 API 额度、或者支付对账不上的经历。2-3分钟的故事，越具体越好）。 这些脏活累活我都准备好了，你直接在上面写你的核心业务就行。

配置即启动，代码只写业务

# 环境变量驱动，填了就开
STRIPE_SECRET_KEY=sk_live_...
POSTHOG_KEY=phc_...
NOWPAYMENTS_API_KEY=...

# 一套代码，三个进程
pnpm dev # Web 前端
pnpm api:dev # API 服务
pnpm worker:dev # 后台任务
使用方式非常简单。环境变量驱动——你填了 Stripe 的 key，支付模块就自动开了；填了 PostHog 的 key，埋点就有了。不需要改一行代码。一套代码跑三个进程：Web 前端、API 服务、后台任务队列。本地 pnpm dev 全合一开发，生产环境分开跑，各自独立扩缩。技术栈是 Next.js 15、tRPC、Prisma、PostgreSQL、Redis、BullMQ，都是现在最主流的选择。换句话说，这套底座本质上是把一个 3-5 人初创团队的建制——前端、后端、运维、商业化运营——压缩到了一个人身上。极大降低了试错成本。

好，代码写完了。到了上线：

K8s？Docker？Nginx？

一人公司的时间极其宝贵。
花在配环境上的每一天，都是在远离用户。

研发效率上来了，但到了上线又是一个坑。很多独立开发者代码写完了，结果花两周去学 K8s、配 Nginx、调 Docker。一人公司的时间是最宝贵的资源，花在这些事上就是在浪费。

velobase.cloud

Git Push → 上线

PostgreSQL Redis 对象存储 自动 SSL 自定义域名

原生理解 Harness 三进程结构，零配置。

让机器管机器，人去想业务。

所以我们做了 velobase.cloud。它原生理解 Harness 的三进程架构——Web、API、Worker 它都知道，你不用写任何配置文件。git push 上去自动构建、自动部署。PostgreSQL、Redis、对象存储、SSL 证书、自定义域名全包了。你不需要会 K8s，不需要凌晨三点收报警。把运维交给平台，你去想怎么获客、怎么定价。
