AI 时代，代码不值钱了

这些事，AI 一秒就能写完：

基础登录页 AI 聊天接口 CRUD 后台 单一支付接入 基础邮件发送 Landing Page

不是壁垒，不产生差异化。

真正值钱的是业务认知

这些事，AI 写不了——因为答案不在代码里：

  • 定价怎么定？积分送多少？怎么引导付费？
  • A/B 跑出来哪个方案赢？转化率卡在哪？
  • 什么行为算滥用？阈值多少？误杀率多少？
  • 分销佣金给多少？怎么防刷？怎么激励？
  • 多端登录体验怎么做到每个端都对？

velobase/velobase-harness

业务认知的基础设施

不是帮你写代码。是把业务认知的地基搭好，
让你专注于调参和决策。

不是模板。是已经在生产跑着、在赚钱的东西。

01

PostHog + A/B 测试

一人公司没有产品经理替你拍脑袋。

数据就是你的产品经理。

改了定价 → 跑个实验
改了落地页 → 跑个实验
改了漏斗 → 跑个实验

从框架层保证：每个业务变更都能被测量。

02

精细化多端登录

NextAuth 三行代码的事？不是。

Web 移动端 Telegram Bot API Token

四条路径，统一身份，各端体验不同。

这个「对」，是靠踩坑踩出来的，不是靠生成出来的。

03

积分 + 订阅 + 支付的组合逻辑

单独一个 Stripe 接入，AI 能写。

但这些组合的设计——是业务决策：

  • 积分充值 + 每日赠送 + 优惠码叠加
  • 续费折扣 vs 一次性付费的比例调控
  • 多支付网关（Stripe / Crypto / Telegram Stars）

框架把执行层接好，你只管调策略。

04

反滥用 + 分销

反滥用

不是写一个 rate limiter。

是：

  • 一次性邮箱放不放？
  • 同 IP 多号怎么判？
  • 风险分多少分拦？

分销系统

不是记录推荐关系。

是：

  • 佣金比例给多少？
  • 提现门槛怎么设？
  • 刷量怎么识别？

管道搭好，你调规则。每个参数都是业务判断。

环境变量驱动，不改代码

# 填了就开，不填就关
STRIPE_SECRET_KEY=sk_live_...
POSTHOG_KEY=phc_...
