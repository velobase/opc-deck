不要让人类限制了 AI

一人公司商业化实践

Jerry · Velobase · 42章经

AI 写代码越来越强了。

但大部分一人公司，还是不赚钱。

我们总觉得——

「是 AI 写得不够复杂。」

我看了很多死掉的项目，发现根本不是这么回事。

我们做出了「功能」

但没做成「生意」

一个能收钱的 SaaS，需要支付、积分、防刷、分销。
没做过生意的人，连这些需求都提不出来。

不是 AI 不行，
是我们不知道该让 AI 做什么。

人类是 AI 的使用主体。
一人公司能不能成，取决于这个「一人」的认知水平。

velobase/velobase-harness

框架 + 文档 = 认知传递

它的价值不是代码本身。
是通过结构和文档告诉你：一个商业化 SaaS 应该具备哪些基础能力。

这是很多研发缺失的认知——不是技术认知，是业务认知。

AI 一句话能搞定的：

登录页 CRUD Landing Page 聊天接口

AI 一句话搞不定的：

精细化多端登录 积分+订阅+多网关计费 PostHog A/B 测试 反滥用策略 分销系统

不是 AI 写不出来，是你不知道要写、不知道怎么设计。

商业 SaaS 里的「脏活累活」

积分 + 订阅 + 支付

充值、赠送、优惠码叠加、多网关
Stripe / Crypto / Telegram Stars

反滥用

一次性邮箱检测、频率限制
风险评分、同 IP 多号判定

A/B 测试 (PostHog)

从框架层保证
每个业务变更都能被测量

分销系统

佣金追踪、提现管理
推荐链接、防刷

这些都准备好了。你指挥 AI 写业务逻辑就行。

底座预设好，AI 只写业务层

# 环境变量驱动，填了就开
STRIPE_SECRET_KEY=sk_live_...
POSTHOG_KEY=phc_...
NOWPAYMENTS_API_KEY=...

# 一套代码，三个进程
pnpm dev # Web
pnpm api:dev # API
pnpm worker:dev # Worker

开发完了。然后呢？

K8s？Docker？Nginx？

又一个让一人公司耗尽精力的坑。
